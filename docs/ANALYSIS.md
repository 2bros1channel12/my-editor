# Local footage analysis

Analysis is opt-in, local, and split into independent `analysis` jobs. Each job names a detector, settings, source asset, validated proxy artifact, and (for transcript-based detectors) the transcript artifact. The resulting JSON file and indexed `analyses` rows are committed with the job output. Job deduplication includes source fingerprint, detector version, normalized settings, and proxy/transcript artifact checksums, so changing one detector setting invalidates only that detector's cache.

Every indexed result includes stable asset ID, source in/out ticks (microseconds), detector ID, human-readable detector name and version, a confidence or signal value, and a plain-language explanation. Output validation checks source bounds, detector provenance, finite signal values, and the presence of confidence or signal strength before commit. Missing confidence is stored as null rather than inferred. Thumbnail signal strength records deterministic sampling success and is not a semantic score; thumbnail cards are shown as timestamp points. Transcript speech-region signal strength is derived from word density and is explicitly not acoustic confidence. The review UI exposes each result's run settings, source fingerprint, and artifact ID. Results have `suggestionOnly: true`; no detector modifies a timeline, source file, or project media. Original media is read-only. Stored source ticks are relative to the first video presentation timestamp, even when a container has a nonzero PTS origin. Proxy timestamps subtract that source origin after applying the recorded source-minus-proxy offset; audio measurements subtract the same origin from the audio stream start before adding exact PCM sample windows. Thumbnail PTS values use the same conversion. Video filters analyze decoded proxy frames and retain FFmpeg `showinfo` timestamps. Audio-energy thresholds report quiet/level intervals only and do not classify speech; speech-region suggestions come from transcript timing. Sampled black/blur durations include the final sample interval and remain cadence-limited estimates.

## Detectors

| Detector | Method | Review caveat |
| --- | --- | --- |
| `silence` | Configurable PCM RMS dBFS entry threshold, hysteresis band, minimum quiet duration, and merge gap; measured in fixed 250 ms windows | Once a candidate starts below the entry threshold, it remains active through the higher exit threshold and configured short gaps to reduce threshold flicker. Only entry-threshold windows contribute to the reported mean quiet-window RMS and duration. Each result also reports its threshold margin. Signal strength is derived from that measured margin, not from the selected threshold alone; it is not calibrated confidence. Quiet speech and room tone can be flagged. Boundary timing is quantized to the measurement windows. Audio timestamps use the original audio stream start and sample windows. |
| `audio_levels` | Mono PCM16 RMS and peak per configurable measurement window, aggregated into approximately one-second result rows | Measures level, not speech or audio quality. Each result reports both measurement and aggregation window sizes. Audio timestamps use the original audio stream start and sample windows. |
| `speech_regions` | Coalesced local ASR word timestamps, labeled possible speech | ASR can omit speech or mis-time words; transcript timing is not independent acoustic verification. |
| `filler_words` | Exact punctuation-insensitive matches for `um`, `uh`, `erm`, and `er` in transcript words, optionally grouping adjacent matches within a configurable gap | ASR can misrecognize words, and hesitations may be intentional. Common words such as “like” are excluded to avoid broad lexical false positives; listen before editing. |
| `shot_boundaries` | Sampled grayscale frame difference; the result spans the full interval between adjacent samples where the change occurred | Flashes, movement, and screen changes can resemble cuts; the interval states sampling uncertainty and is not a frame-accurate edit point. |
| `near_black` | Fraction of pixels in the central 80% image area under a configurable luma threshold | Fades and intentionally dark scenes can trigger it. Cropping the outer 10% reduces edge-bar influence, but thick letterboxing can remain in the measured area. |
| `blur` | Median sampled Laplacian variance over a low-edge-energy segment | This resolution- and content-dependent signal is not a blur probability; smooth backgrounds and low-detail frames can look blurred. |
| `thumbnails` | Evenly spaced frames from the validated proxy, recorded as timestamp points | Representative by spacing, not semantic content. |
| `motion` | Mean frame-to-frame pixel change in time windows | Camera movement and cuts also increase activity. |
| `repeated_takes` | Transcript text similarity plus duration similarity across separated passages. A multiset similarity upper bound skips full sequence comparisons only when they cannot reach the configured combined score. Matching considers at most 2,000 passage pairs and skips individual passages longer than 500 words. | Repeated phrasing or coincidental similarity may be suggested. Reaching either safety bound produces a committed warning shown in the interface; the result set may be incomplete. |

All detector settings are validated and bounded in the service catalog and can be changed per run. Unknown setting keys are rejected so misspellings do not silently run with defaults. Audio- and transcript-based detectors report the measured source ranges. Video sample cadence bounds temporal precision; shot boundaries are small windows around sampled changes, not frame-accurate edit points. Thumbnails are exposed through ticketed loopback URLs only after proxy validation.

Transcript-derived detector jobs also fingerprint the current reviewed transcript state (edited segments/words and required, excluded, or uncertain markers), in addition to the immutable inference artifact checksum. A review change therefore produces a distinct cache input. Filler suggestions use exact source word timestamps, retain backend confidence when provided, and store the configured grouping gap in their independent cache key. Repeated-take cards show both transcript passages and their text/duration similarity alongside source-synchronized seek controls.

The review service reports current source availability, a registered proxy with its required files present, whether its audio-only analysis file exists, and whether a current transcript artifact is available. The UI disables runs with missing prerequisites and points to Projects or Editor for the next step. Polling reuses a process-local digest only while every artifact file's path, size, and modification time remain unchanged; the explicit Refresh action forces a fresh content hash. Jobs continue to hash source and proxy inputs directly before decoding and committing results.

Results are grouped by committed artifact run. The review interface defaults to the newest run for the selected detector and offers prior individual runs or all cached runs. Each row shows its run settings and provenance so settings-specific history remains understandable.

The analysis response compares current source-file size and modification time with the values recorded at import. A mismatch or missing path triggers a visible warning while retaining historical results. This is a quick staleness indicator, not a cryptographic re-hash; jobs themselves still verify the full source fingerprint before and after analysis.

When listing results, the service verifies each backing analysis artifact checksum and confirms the indexed SQLite result exactly matches its row in the artifact payload. It verifies the current proxy bundle checksum, then compares recorded proxy and transcript artifact IDs/checksums with the current project records. It also compares the saved detector version with the currently registered algorithm version. The UI labels mismatched/corrupt artifacts as invalid and results with changed source/proxy/transcript lineage or outdated detector versions as stale while retaining them for history. An intact artifact with matching recorded lineage and current detector version is labeled as such; this is not a fresh source-media hash. The results page uses file size and modification time to avoid repeatedly hashing large source recordings during job polling.

## Failure and recovery

The existing persistent queue controls progress, cancellation, retry, restart recovery, and partial output cleanup. Cancellation and failures do not register analysis rows. A detector reports completion only after its JSON output passes range and signal validation, the cache artifact is atomically published, and its index rows commit. The source, proxy checksum, and referenced transcript checksum are checked before and after analysis. Regenerate a proxy or transcript when those inputs change. Each detector has its own artifact kind (`analysis:<detector>`) and cache key.

The independent detector-choice review favored deterministic pixel/audio/transcript signals with readable configuration and source-linked comparisons. The false-positive review emphasized that cuts, speech, blur, darkness, activity, and repeated takes remain ambiguous cues; their explanations state likely confounders, and all are suggestions only. Audio-level and silence results retain measurement units/window settings and map using audio start plus proxy alignment. Shot-boundary intervals cover the full adjacent sample pair and use source-relative PTS even for nonzero timestamp origins. Near-black scoring ignores persistent bars in the central 80% of the sampled proxy frame; synthetic checks cover both a bright 4:3 image letterboxed in 16:9 and a dim content area where bars are also present. Dark image content remains a valid near-black suggestion and is explicitly caveated. Blur signals use a median across the full candidate segment. Repeated-take comparisons skip passages shorter than four transcript tokens, skip passages longer than 500 words, and expose both ranges and match components; pair-count and passage-size limits are surfaced as warnings even when the run finds no pair. Changed detector algorithms bump their version, producing a separate cache identity. Decoded grayscale frames are written to bounded job staging output and consumed one at a time, so frame memory stays constant with source duration; cancellation and recovery remove the staging file.

Before a video detector starts decoding, it estimates grayscale frame-staging size from source duration and the selected sample rate, adds a fixed/relative reserve, and checks free space on the job-staging volume. It fails before invoking FFmpeg when the estimate does not fit and reports the estimated and available space. This covers the detector's temporary sample frames; it is not a full-project disk quota or an estimate for source media, proxy bundles, or exports.

Video frame sampling sends FFmpeg progress on a separate stdout channel while decoded grayscale frames go to a staging file. The persistent job reports sampling progress from FFmpeg's processed-time counter; it does not interpret that counter as an exact decoded-frame count.

Run the focused suite with `service/.venv/Scripts/python.exe -m pytest service/tests/test_analysis.py` from the repository root; run the interface suite with `npm test -- --run`.

Audio-level cards display RMS and peak in dBFS and identify the values as measurements rather than confidence. Silence cards display the measured mean quiet-window RMS and threshold margin; the signal strength is based on that observed margin and is not calibrated confidence. Other cards label signal values with detector-specific measures; signal strength is not calibrated confidence. Transcript confidence remains separately identified as backend confidence.


## Sampling and cancellation updates

Pixel detectors (`shot_boundaries` v4, `near_black` v3, `blur` v3, and `motion` v2) normalize the complete proxy image to a 160×90 grayscale measurement grid without introducing synthetic black padding. This preserves the full image for measurement and prevents portrait padding from diluting change/activity signals or dominating dark-pixel counts. This grid is only a detector input; displayed proxies and original footage retain their aspect ratio. Normalizing different aspect ratios changes spatial scale, so blur thresholds remain aspect- and resolution-dependent. Existing bars encoded in the footage can still affect measurements; the near-black detector excludes the outer 10% of the normalized image to reduce their influence.

FFmpeg's `fps` filter selects samples on an output grid. `showinfo` records those grid timestamps, not the exact originating VFR frame timestamps. Every pixel-detector suggestion now includes `timingMethod: proxy_sample_grid`, `sampleIntervalSeconds`, and a visible explanation of cadence-limited timing. These are review intervals, not exact frame edit points. Proxy/source offset and nonzero source origins are still applied before recording source-relative microsecond ranges. Representative thumbnails continue to use their separately recorded source frame PTS.

Execution-time integrity checks now accept cancellation between source-file chunks, bundle entries, and artifact-file chunks. Transcript grouping and thumbnail selection also check cancellation. Cancellation still discards staging output and commits neither artifacts nor analysis rows. Submission-time input validation has no active job cancellation context; validating a large input before it is queued can still take time. Repeated-take output validation checks both the suggested source range and the comparison range for integer timestamps, ordering, and source-duration bounds.

Regression coverage includes cancellation during source and proxy verification, cancellation while grouping transcript-only speech/repeated-take inputs, malformed comparison ranges, independent detector-version cache invalidation, and sampled timing disclosures, in addition to the existing nonzero-origin, irregular-cadence, cache-lineage, and process cancellation tests.
