# Creative briefs and first-cut proposals

See [guided briefs and project workflow](GUIDED_BRIEFS.md) for the expanded guided questions, generic style recipes, creator-inspiration review, schema version 2 constraints, and opening existing native projects.

The Editor stores each brief revision in the project's SQLite database. `brief_parse` uses a versioned deterministic labeled-field parser and makes no network or model calls. The user can edit audience, objective, tone, target duration, aspect ratio, must-keep topics, must-remove topics, and optional preferred passage order before saving. Accepted labels include `Audience`, `Objective`/`Goal`, `Tone`, `Target duration`, `Aspect ratio`, `Must keep`, `Must remove`, and `Preferred order`/`Passage order`. Unlabeled prose becomes a draft objective.

`proposal_generate` queues one `suggestion` job for a selected source, saved brief revision, and transcript. Its cache identity includes the source fingerprint, brief revision, transcript artifact checksum, transcript review-state fingerprint (edited text, word state, and range markers), and generator/pipeline versions. The job validates the source and transcript artifact before and after analysis. The committed artifact and indexed edit plan carry source, transcript, brief, and generator provenance.

The deterministic proposer groups source-timed words across short gaps. Required transcript ranges and must-keep topic matches take precedence over excluded ranges and must-remove phrases. Existing timeline clips that overlap excluded source ranges receive separate pending exclusion operations. When no clip exists yet, omitted ranges are recorded in the plan rationale and do not create no-op timeline operations. Candidate include passages remain separate, in source order, with transcript confidence when available and uncertainty flags where timing or markers require review. A target-duration overrun is reported; content is not dropped only to satisfy a target.

If the brief names a preferred order, each phrase must match exactly one distinct kept passage. Missing, ambiguous, or duplicate phrase matches produce a warning and no reorder operation. A valid order produces one separate pending `reorder_passages` operation with source ranges and IDs for every kept passage; passages named in the brief come first in that order, and unspecified passages follow in source order. The user must accept every kept-passage operation before the reorder can be accepted. Applying it changes only timeline positions, preserves each source range and linked caption timing, and is undoable. It is restricted to an uninterrupted block of the proposal's clips at the end of the video track so surrounding edits are not shifted.

No operation changes a timeline until the user accepts it. Acceptance supplies the project revision that was reviewed, and is rejected if the project changed in the meantime. Each accepted operation creates an autosave/recovery revision. Undo restores the exact immediately preceding timeline state only while no later project edit exists. If later changes have occurred, use normal timeline history rather than restoring an old whole-timeline snapshot. Rejection changes only proposal status.

The proposer uses only the saved neutral `pacing` and `punchInFrequencyPerMinute` traits from an approved profile; it does not use creator identity, branding, signature assets, or a language model. Fast, moderate, and slow preferences set natural speech-gap grouping thresholds of 0.7, 1.2, and 1.8 seconds. This only changes where candidate transcript passages split: it does not remove speech or authorize reordering. The saved punch-in frequency caps the number of subtle 110% punch-in suggestions for the source duration, and suggestions are limited to brief-protected passages. Both traits and their analyzer provenance are part of the job cache identity and are shown with the proposal. Caption density, music energy, humor, narrative structure, and the measured numeric pacing traits remain visible/editable but do not affect first-cut generation yet. The user must first accept a related kept passage, then accept a punch-in independently. The crop changes only a timeline clip property and can be undone. When accepting an include operation, the user can also opt to create editable caption cues from reviewed transcript segments in the same atomic timeline save. Captions retain transcript source ranges and generator provenance, use corrected segment text when the accepted passage contains the full segment, and use intersecting word text where the passage clips a segment boundary. SRT export uses accepted caption text. Captions remain editable; MP4 export can optionally burn them in when the configured FFmpeg build supports the subtitle filter.
