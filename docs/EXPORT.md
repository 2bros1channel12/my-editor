# Local export

## Caption and finishing controls

Timeline now offers **Generate editable captions** from current word transcripts. Configure 5–40 characters per second, 10–80 characters per line, 1–3 lines, 5–20% safe margins, and plain, boxed, or large styles. Words outside a trimmed clip are omitted rather than assigned invented timing. Fast speech is flagged for review; generation never extends a caption outside its source words. Existing captions remain, and a generation batch is one undoable edit. Select a caption to edit its text. Stored caption styles and safe margins are included in burned ASS captions; manual captions use the export panel's fallback style. SRT carries timing/text only.

The export panel offers final or preview quality, short-edge resolution 480/720/1080, and 24/25/30/50/60 fps. Preview is capped to 720 and uses CRF 28; final uses CRF 20. Both read original media and produce standalone review MP4s in `exports/`; preview quality does not require or reuse proxy files. All settings enter the render fingerprint and completed export history. Extreme output aspect ratios exceeding a 4096-pixel long edge fail with a smaller-resolution suggestion.

Speech gain affects linked clip audio; music beds retain their own gain. Optional FFmpeg `afftdn` noise reduction runs on speech before mixing and fails actionably if unavailable. Optional single-pass `loudnorm` runs after mixing with a configurable -24 to -9 LUFS target; it is a finishing target, not a measured compliance guarantee. Every mix uses a latency-compensated limiter at approximately -1 dBFS with automatic makeup gain disabled. Browser playback does not simulate these mastering filters; render a preview to hear them. Newly named tracks are included; overlapping video layers still fail explicitly.

For imported music, use an MP4/MOV with an audio stream, add an audio track and insert its source range. Selecting the audio item exposes editable rights/license and attribution fields. These fields persist and undo with the timeline and travel in OTIO metadata. Standalone MP3/WAV import and automatic on-screen attribution are outside this slice.

## Editable interchange

Completed MP4s can be played directly in the export panel. The service checks the stored export checksum and containment within the project exports folder before issuing a local playback ticket. Corrupt or modified files fail with a request to render again. The persistent Jobs panel retains stage/progress events and actionable render errors; retries keep the captured settings and reject stale edit snapshots.

**Export editable OTIO** writes OpenTimelineIO JSON atomically and registers it in export history. Source clips use original file URIs, exact microsecond source ranges, stable IDs, track placement, explicit gaps, and separate linked audio tracks. Markers are exported. Captions, gain, fades, crop, provenance and music rights are preserved in namespaced `localcut` metadata. Other editors may not reproduce these effects; they are not advertised as portable effect instructions. OTIO reading was validated with official OpenTimelineIO 0.18.1. The SDK is optional for development validation and is not a runtime dependency. External editors need access to the referenced original files.

New RPCs are `caption_generate(path, expectedRevision, settings)` and `export_otio(path)`. `export_generate` accepts a closed `options` object; arbitrary filters, codecs, paths, or shell commands are rejected. Existing progress, cancellation, restart recovery, retry, staging cleanup, disk reserve checks, full decode and A/V validation apply to both render modes. Noise filtering, rendering and decoding are cancellable process stages. Failed exports preserve prior completed exports.

The Editor's export panel queues an H.264/AAC MP4 render as a persistent `rendering` job. The job captures the current project revision, timeline revision, source asset IDs, and source fingerprints. Before and after rendering it checks that the edit snapshot is still current and hashes linked source files against their import fingerprints. A stale edit or changed/missing source fails with an actionable message; the source media is read-only.

FFmpeg receives an application-built argument list and filter graph; no shell is used and user text is never interpolated into a command. The renderer supports sequential video clips across named tracks at normal speed, explicit timeline gaps (black video and silence), right-angle source rotation, full-frame or centered punch-in presets, linked source audio, clip gain, and audio fades. Each clip may fade in from black or fade out to black; these simple fade-through-black transitions keep clips sequential and do not overlap source ranges. Cross-dissolves are not supported. User-supplied music/audio bed items can reference an imported MP4 or MOV audio stream, with source in/out, timeline placement, level, and fades. Beds are resampled and delayed to their timeline start, mixed under the linked video audio, limited against clipping, and truncated to the video duration. A bed source without audio or a range outside the video duration fails before rendering. The app does not extract or retain music from optional creator references. The renderer follows the latest saved brief's aspect ratio (`source`, 16:9, 9:16, 1:1, or 4:3), using the first clip's display ratio when set to `source`, uses the selected short-edge resolution, and uses the explicitly selected constant output frame rate. H.264/AAC output is written to job staging, probed for codec, dimensions, and duration, and decoded in full before the persistent queue atomically publishes it under `exports/` and records a checksum and timeline revision. Cancellation and failure discard the partial output and leave prior exports intact.

Accepted timeline captions can be exported separately as an atomically written UTF-8 SRT sidecar. The MP4 export panel also offers an explicit burned-in caption choice. For that mode, caption ranges must be positive and fall within the rendered timeline, and text must contain 1–4,000 characters. The job checks the installed FFmpeg filter list for `ass` or `subtitles`, writes a temporary ASS file in its private staging directory, and references the fixed basename while running FFmpeg with that directory as its working directory. Caption text is escaped for ASS markup; the file and partial video are removed through normal job cleanup. A build without libass support fails with an actionable error and does not publish an export. The selected mode is included in the render fingerprint and export history. The canonical editable timeline remains unchanged by either export.

Known current limits: this render profile rejects overlapping clips and non-normal-speed clips; a clip whose timeline/source durations differ is not resampled. It does not render overlays or cross-dissolves. The output is validated for H.264, requested dimensions, timeline duration within one output frame, complete decode, and FFprobe audio/video stream start and end alignment within one output frame. Missing or non-finite stream timestamps/durations fail closed. Measured audio-minus-video start and end offsets are retained in job output and completed export history and shown in the Export panel. Endpoint checks detect cumulative stream-duration drift, but do not detect temporary drift inside the file or acoustic content misalignment; corpus-based sync validation remains part of release validation.

Before building an FFmpeg filter graph, the renderer rejects non-finite/out-of-range audio gains and malformed, negative, or out-of-clip fade times. Fade durations longer than half a clip are capped to half its duration, matching the editor's control limits. This avoids silently translating corrupted project settings into unintended audio/video changes. The renderer version is part of export provenance and cache identity.

`service/tests/test_render.py` also verifies that an end-alignment failure in a later render leaves a previously completed export and its history intact. `service/tests/test_render_ffmpeg.py` contains real-tool integration and optional release-duration checks. Set `LOCAL_CUT_TEST_FFMPEG` and `LOCAL_CUT_TEST_FFPROBE` to a local FFmpeg/FFprobe pair, then run `service/.venv/Scripts/python.exe -m pytest service/tests/test_render_ffmpeg.py -q` from the repository root. The default short synthetic source checks the complete export job, H.264/AAC codecs, duration, decode completion, visible burned-in captions compared with a clean render, SRT caption text, stream-start and stream-end alignment, and unchanged source bytes. To run the 10-minute 1080p30 case on recommended hardware, also set `LOCAL_CUT_RUN_LONG_RENDER=1`. This measures a synthetic render pipeline run; it does not replace content-level lip-sync, caption accuracy, or usability validation on representative creator footage.
