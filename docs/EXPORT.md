# Local export

The Editor's export panel queues an H.264/AAC MP4 render as a persistent `rendering` job. The job captures the current project revision, timeline revision, source asset IDs, and source fingerprints. Before and after rendering it checks that the edit snapshot is still current and hashes linked source files against their import fingerprints. A stale edit or changed/missing source fails with an actionable message; the source media is read-only.

FFmpeg receives an application-built argument list and filter graph; no shell is used and user text is never interpolated into a command. The renderer supports the current single video track at normal speed, sequential clips, explicit timeline gaps (black video and silence), right-angle source rotation, full-frame or centered punch-in presets, linked source audio, clip gain, and audio fades. Each clip may fade in from black or fade out to black; these simple fade-through-black transitions keep clips sequential and do not overlap source ranges. Cross-dissolves are not supported. User-supplied music/audio bed items can reference an imported MP4 or MOV audio stream, with source in/out, timeline placement, level, and fades. Beds are resampled and delayed to their timeline start, mixed under the linked video audio, limited against clipping, and truncated to the video duration. A bed source without audio or a range outside the video duration fails before rendering. The app does not extract or retain music from optional creator references. The renderer follows the latest saved brief's aspect ratio (`source`, 16:9, 9:16, 1:1, or 4:3), using the first clip's display ratio when set to `source`, caps the long dimension at 1920 pixels, and selects an output frame rate from that clip (bounded to 1–60 fps). H.264/AAC output is written to job staging, probed for codec, dimensions, and duration, and decoded in full before the persistent queue atomically publishes it under `exports/` and records a checksum and timeline revision. Cancellation and failure discard the partial output and leave prior exports intact.

Accepted timeline captions can be exported separately as an atomically written UTF-8 SRT sidecar. The MP4 export panel also offers an explicit burned-in caption choice. For that mode, caption ranges must be positive and fall within the rendered timeline, and text must contain 1–4,000 characters. The job checks the installed FFmpeg filter list for `ass` or `subtitles`, writes a temporary ASS file in its private staging directory, and references the fixed basename while running FFmpeg with that directory as its working directory. Caption text is escaped for ASS markup; the file and partial video are removed through normal job cleanup. A build without libass support fails with an actionable error and does not publish an export. The selected mode is included in the render fingerprint and export history. The canonical editable timeline remains unchanged by either export.

Known current limits: this render profile rejects overlapping clips and non-normal-speed clips; a clip whose timeline/source durations differ is not resampled. It does not render overlays or cross-dissolves. The output is validated for H.264, requested dimensions, timeline duration within one output frame, complete decode, and FFprobe audio/video stream start and end alignment within one output frame. Missing or non-finite stream timestamps/durations fail closed. Measured audio-minus-video start and end offsets are retained in job output and completed export history and shown in the Export panel. Endpoint checks detect cumulative stream-duration drift, but do not detect temporary drift inside the file or acoustic content misalignment; corpus-based sync validation remains part of release validation.

Before building an FFmpeg filter graph, the renderer rejects non-finite/out-of-range audio gains and malformed, negative, or out-of-clip fade times. Fade durations longer than half a clip are capped to half its duration, matching the editor's control limits. This avoids silently translating corrupted project settings into unintended audio/video changes. The renderer version is part of export provenance and cache identity.

`service/tests/test_render.py` also verifies that an end-alignment failure in a later render leaves a previously completed export and its history intact. `service/tests/test_render_ffmpeg.py` contains real-tool integration and optional release-duration checks. Set `LOCAL_CUT_TEST_FFMPEG` and `LOCAL_CUT_TEST_FFPROBE` to a local FFmpeg/FFprobe pair, then run `service/.venv/Scripts/python.exe -m pytest service/tests/test_render_ffmpeg.py -q` from the repository root. The default short synthetic source checks the complete export job, H.264/AAC codecs, duration, decode completion, visible burned-in captions compared with a clean render, SRT caption text, stream-start and stream-end alignment, and unchanged source bytes. To run the 10-minute 1080p30 case on recommended hardware, also set `LOCAL_CUT_RUN_LONG_RENDER=1`. This measures a synthetic render pipeline run; it does not replace content-level lip-sync, caption accuracy, or usability validation on representative creator footage.
