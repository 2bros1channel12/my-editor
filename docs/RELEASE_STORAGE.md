# Privacy and storage controls

Local Cut has no telemetry sender or media upload workflow. The privacy status reports this default policy, the configured numeric loopback model endpoint, and known queued/running model download jobs. It is an application activity status, not an operating-system network monitor. Explicit catalog model downloads contact Hugging Face and its download CDN; media is not sent. Download catalog entries disclose source URL, pinned revision, expected size, license and SHA-256. Existing downloads validate size and SHA-256 before publication; retry restarts an interrupted transfer, rather than resuming arbitrary unverified bytes. Externally managed Ollama/llama.cpp model storage remains controlled by that provider.

`privacy_status` reports project, cache, transcript artifact and model byte totals. `storage_review` returns current scope, affected bytes/files, active jobs, a detail string and an edit/filesystem-bound confirmation token. `storage_remove` requires this token and an idle project. Model scope removes that catalog model's downloaded/invalid files and invalidates model artifacts; it retains transcripts. Transcript scope removes inference transcript rows and transcript/search artifacts, discards old recovery snapshots and creates a fresh purged checkpoint. Captions, accepted edits, timeline undo history, briefs, plans, exports and their evidence remain. These controls do not claim forensic secure erasure, and transcript cleanup is not a promise to erase text copied into accepted editorial work or central terminal job snapshots.

Complete project deletion removes the entire chosen native project folder, including managed media copies, exports, model weights, caches, inferred transcripts and recovery data. A `ProjectCatalog` pointer to that project is cleared. The service also forgets the project's terminal central queue jobs and publications; active jobs must be cancelled or completed first. Local rotating diagnostic logs may retain event IDs or bounded diagnostic paths and are outside project deletion. Operating-system backups, external copies and filesystem forensic remnants are outside app control.

The storage code refuses filesystem roots/home paths and symbolic links or Windows junctions. Each complete deletion validates the exact native project and reviewed file inventory, then renames it to a unique sibling `.deleting-<UUID>` directory before removing files. If removal is interrupted after this rename, the project is not reopenable at its previous path; an actionable error names the exact remaining folder to finish removing. This is not a recoverable-trash command.

Import now records `localcutManagedCopy`, original source URI and original SHA-256 in asset metadata only after Local Cut creates a distinct verified managed copy under `media/`. Imported metadata cannot supply this ownership marker. Relinking to a different actual path clears it. This makes it possible to delete managed copies without treating every portable relative source path as owned media. Deletion refuses contained linked originals, managed-copy originals still present inside the project, and legacy contained sources whose managed ownership is unknown. Move/relink those originals outside the project before deletion; the app does not guess ownership from a filename. Projects with ordinary external linked sources and newly recorded app-owned managed copies support complete deletion.

Destructive storage operations and new/retried job registration share a process lock. Model/transcript removal also retains a SQLite write lock across its reviewed filesystem changes. Windows requires the project database connection to close before the project directory can be renamed; the process lock blocks job registration over that interval. Project open requests remain serialized by the service request loop, and the persistent queue enforces a single service owner.
